### 35.1 Settlement headings, button art and equipment slots (#745)

- **Seen:** @YuriRestia's #745 reports translated outcome headings overlapping the official layout, buttons mixing
  official sprites with CSS decoration, and equipped items overflowing their two slots. The dev mock had no gear.
- **Official / decision:** retain @isomerpoi's #698 screen and the maintainer-approved official look (§34.34).
  The official client's `autochessouter/settlegame/auto_chess_settle_game_state` sprites are indexed in
  `docs/research/07-assets.json` → `autochessUi.settle`: `btn_next_bg`, `btn_bg_02`, `operator_frame` and
  `operator_trap_bg` (asset pipeline: `docs/ASSETS.md`). No match, reward or equipment rule changes.
- **Cause:** absolutely positioned headings had no width budget; button CSS always painted behind the sprite;
  percentage-sized images could determine the flex/grid slots' intrinsic minimum sizes, with the screen's broad
  `max-width: none` image rule removing the normal cap.
- **Now:** both headings scale uniformly inside fixed boxes, remeasured when language, fonts, viewport or text size
  changes. The three buttons render CSS decoration through the existing Sprite missing/failed-image fallback only;
  keyboard focus still has a visible ring. Equipment slots have zero minimum sizes and bounded grid tracks, with
  contained images capped to the slot. `game-mock.html?phase=RESULT&variant=equipped` supplies two/one/no-item rows.
- **[ASSUMED]:** the browser's title budgets (personal 7.8 × 1.04rem, alliance 2.8 × 0.9rem) and shrink-to-fit behavior
  are translation/accessibility accommodations, not official client measurements. Keep #698's short-label size,
  screen positions, two-slot layout and fallback artwork. This change adds no gameplay assumptions.
- **Tests:** `test/ui/settle.test.js` adds title fitting, mutually exclusive button decoration and equipped-card
  regressions. `test/ui/settle.e2e.test.js` checks both pages in zh-CN/en/ja/ko/zh-TW, 1280×720 and 844×390, with
  loaded/failed art and all four text sizes; `SP_SETTLE_SHOTS=<dir>` writes personal screenshots
  at that path and alliance screenshots under `team/`. The test loads the real language index before switching:
  the dev mock skips `main.js`'s `initLang()`, so otherwise only Chinese is registered and unknown codes normalize
  to Chinese without fetching a pack. Language warnings are included in failures. All 20 cases passed three runs in a row before the merge.
  Golden results must remain unchanged.

### 35.2 Minimum-Python parsing guard for the local extractor (#744)

- **Seen / cause:** `tools/local-extract/fx.py:2987` uses nested same-quote f-string syntax that Python before 3.12
  cannot parse; the Node checks do not compile the extractor. @zasx77771's #744 fixes that line separately.
- **Official / contract:** this is tooling, with no official gameplay rule. `tools/setup.mjs` → `findPython()` accepts
  Python 3.8+. The [setup-python action documentation](https://github.com/actions/setup-python#basic-usage) names
  major v7; checkout stays on v7 like `.github/workflows/ci.yml`.
- **Now:** the separate `local-extract-python.yml` workflow runs `python -m compileall -q -f tools/local-extract` on
  Python 3.8 for pushes, pull requests and manual runs, with read-only contents permission and a five-minute timeout.
  It needs no extractor dependencies or official files. `ci.yml` and its exact `test/ci.test.js` contract are unchanged.
- **[ASSUMED]:** five minutes is a CI resource budget, not a game rule. The guard checks syntax, not extractor runtime
  compatibility. It intentionally remains red until #744 merges; `fx.py` is not edited by this change.
- **Tests:** `test/local-extract-python-ci.test.js` ties the interpreter floor to setup, checks triggers/permissions,
  action versions and the compile command; `test/ci.test.js` retains the local CI contract. Locally, Python 3.14.3
  compiles the tree; Python 3.9.6 fails at the expected `fx.py:2987` f-string. Python 3.8 is not installed here.

### 35.3 Optional selected-unit bond timers (#746)

- **Seen:** @Realzhazha's #746 asks to see the remaining duration of Siracusa, Sargon and similar timed effects.
- **Official / decision:** local `activity_table.json` → `activity.AUTOCHESS_SEASON.act2autochess.bondInfoDict` →
  `sargonShip.desc` explicitly gives each stack an independent duration, with equal-duration ATK at six members.
  `siracusaShip.desc` separates deployment ASPD, equal-duration stealth at six members, and the ten seconds after
  stealth for the attack proc. `server/sim/content/bonds/core.js` implements those effects with `timeLeft` and
  `mem.siraStealthEnd`; the post-stealth length comes from `act2autochess_bond_eff_siracusa.end_duration` in the
  generated bond blackboard, the same data used by the proc. The maintainer approved this optional convenience
  on 2026-10-18 (round49 triage D3 / #746), OFF by default, following the ammo/energy count switch (§34.3).
- **Cause:** the simulation kept these times but neither the render snapshots nor the selected-unit card exposed
  them. The existing live-stat RPC alone would omit server-run fields.
- **Now:** 设置 adds「盟约效果剩余时间」beside the ammo/energy switch, persisted as boolean `bondTimers` in
  `sp.pref.settings`. The selected card shows Sargon's active stack count and next stack expiry; Siracusa has separate
  deployment ASPD, deployment stealth and post-stealth proc-window rows. Early stealth removal starts only the
  post-stealth row; ASPD may continue independently. Expired/removed effects and dead/undeployed/hidden units have
  no rows. `shared/bondTimers.js` declares the four effect identities, sources and translated labels; another mapped
  effect can be added by declaration. Only these two bonds are wired.
  Optional snapshot `bondTimers` rows carry remaining simulation seconds. Local, Worker and server fields use the
  same data; pause freezes it and speed changes simulation progress. Reconnect needs no event history, spectators
  use the watched field, field re-entry clears old data, and absent rows clear the card. Prep previews show none.
- **[ASSUMED]:** the official game has no such numeric HUD. The convenience readout, labels, stack-count/next-expiry
  summary, rounding upward to 0.1 seconds and 250 ms card refresh are presentation choices, not official rules.
  The card holds the latest received values between snapshots, including network stalls; it never extrapolates with
  wall-clock time. A missing/junk preference stays off; only boolean `true` enables it. This adds no gameplay rule.
- **Tests:** `test/content/bond-timers.test.js` covers independent expiry, layers, cap, early removal, natural expiry,
  death, redeployment and read-only snapshots; `test/match/bond-timers.test.js` covers real Worker parity, 1×/2×,
  pause, watched fields and fresh catch-up; `test/ui/bond-timers.test.js` covers defaults, filtering and translations.
  `test/ui/bond-timers.e2e.test.js` is `SP_E2E=1` gated: settings persistence, live card updates, missing/dead rows,
  foreign-field isolation, five languages and 1280×720 / 844×390 at XL text; both cases passed before the merge.
  Golden scenarios are unchanged: `tools/golden.mjs`'s existing canonical snapshot explicitly selects gameplay
  fields and excludes this optional display metadata; neither the tool nor any golden JSON was edited.

### 35.4 Picture-only outfits (B6)

- **Seen:** the 0.3.1 known issue excluded outfits with avatars / portraits but no Spine, including Forge skin-catalogue
  outfits already imported into the skins layer. Cards and panels also continued reading the default pictures.
- **Official / decision:** the maintainer chose option A on 2026-10-18: those outfits become wearable, labelled
  「仅更换头像与立绘」, with the default battle model and independent missing-picture fallbacks. The official
  [skin_table.json](https://raw.githubusercontent.com/Kengxxiao/ArknightsGameData/master/zh_CN/gamedata/excel/skin_table.json)
  `charSkins` separates `skinId`, `charId`, `avatarId`, `portraitId`, `illustId` and `battleSkin` (for example
  `char_285_medic2#1`). Local `activity_table.activity.AUTOCHESS_SEASON.act2autochess.charShopChessDatas`
  `chess_char_3_01_a` still maps `char_103_angel` to `backupCharId: char_603_csnipe`. Missing plugin models are a
  remake presentation policy, not an official gameplay rule.
- **Cause:** `availableSkins().playable` required `skinHasModel`, and the picker filtered out everything else.
  DOM card URL helpers never received an owner's selection; result and foreign-detail paths dropped the owner.
- **Now:** a model or pictures enables an outfit; the global picker gate stays global. `OperatorImage` and the pure
  URL helpers apply each owner's public choice to cards, details, bond members and result pictures; the local picker
  uses its own saved choices. Stand-ins / DIY resolve their effective body first. Open images follow choice, visibility
  and manifest changes; public clears beat stale unit metadata. The combat meter retains effective-body picture
  metadata; the DOM fallback field accepts the same seat / choice updates. Spine resolution retains default Front / Back for picture-only skins and skin models for model
  outfits. No wire, importer, simulation or generated-data changes. Normative updates: SKINS.md, PLUGINS.md §9,
  design/client.md §9, DESIGN index and PLAYING.md; the previous model-only limitation is removed.
- **[ASSUMED]:** the existing E2 and illustration fields count as pictures, while metadata alone does not. An unfinished Spine
  map without Front uses both default views. E2-only art replaces only elite images in play. Picture fields keep the existing normal / elite fallback order; portrait
  may use the outfit's illustration, avatars never do. Card updates follow the renderer's latest public map (including
  clears), then unit metadata if the owner is unavailable; they never borrow the viewer's choice for another seat.
  Unowned catalogue / studio comparison / historical statistics images retain defaults. These choices do not alter gameplay.
- **Tests:** `test/ui/picture-skins.test.js` covers picker eligibility, two owners / spectators / visibility / clears,
  individual image fallbacks, normal / elite art, default Front / Back and model outfits, effective stand-in / DIY
  bodies and owner propagation through cards / details / results. `test/match/combat-metrics.test.js` adds
  effective-body / elite picture metadata coverage. Updated picker and stand-in UI tests retain prior behavior. `SP_E2E=1 node --test test/ui/picture-skins.e2e.test.js` mounts the production picker, shop card and avatar
  with original synthetic PNGs and checks note layout (desktop / landscape phone), selection, persistence, distinct
  seats, public changes / clears, visibility off/on and plugin removal.
  The browser check passed before the merge. Golden scenarios unchanged.

### 35.5 Re-entrant buff removal

- **Seen:** round49's API reproduction staggers two Sargon stacks, lets the older expire, then explicitly removes
  the last stack; the call throws after clearing its ATK aggregate. The same happens after overflowing the 25-stack
  cap. An extension clearing all six members stops after the first; no current vanilla caller is known to reach it.
- **Official / contract:** local `activity_table.json` → `activity.AUTOCHESS_SEASON.act2autochess.bondInfoDict.sargonShip`
  specifies independent stack durations and equal-duration ATK for six different members.
  `effectBuffInfoDataDict.bondeffect_sargon` → `act1autochess_bond_eff_sargon` gives ASPD +12, ATK +12%, duration
  `5 + 0.22L` seconds and cap 25, disabled ATK in `band_narant`. These gameplay rules remain unchanged.
  The requested fix defines the remake's helper traversal; official tables do not specify JavaScript callback order.
- **Cause:** `removeBuff` walks the mutable list backwards by index. Sargon's synchronous `onRemove` calls `syncAtk`,
  which removes the ATK aggregate when the final stack disappears. After `[S1, A, S2]` becomes `[A, S2]` by expiry,
  removing S2 also removes A; the outer loop then reads `undefined.key` through its stale index.
- **Now:** fix the matching objects in reverse order before callbacks, then find each in the current list by identity.
  Only present objects pass through `_removeBuffAt` and count toward this call's return value; nested removals have
  their own counts and skipped objects receive no second callback. The existing path preserves intermediate stack
  counts, dirty stats, flags, status events and `onRemove` versus `onExpire`. A clearing hook can finish all six units
  and continue; its `once` handling remains intact. Normative additions: design/engine.md §5.3, SIM.md §3 and DESIGN index.
- **[ASSUMED]:** fixing this call's candidate set, retaining reverse callback order, skipping already removed objects
  and leaving new same-key instances for later calls are extension API policies, not additional official game rules.
  Explicit clearing in these tests models a plugin / kit call, not a demonstrated vanilla gameplay trigger.
- **Tests:** `test/content/sargon-remove-buff.test.js` covers the staggered two-stack / ATK case and a six-member
  extension batch at the 25-stack cap, including unique reverse callbacks, per-removal ATK sync and continuation.
  `test/sim/remove-buff.test.js` covers nested matching / unrelated removals, actual counts, flags, status events,
  callback-added same-key instances and absent-object / null no-ops. All four fail before the fix.
  Golden scenarios must remain unchanged; neither the golden tool nor its JSON files are modified.

### 35.6 Strategy-draft match information (#484, PR #561)

This is a post-release addition and is not included in published 0.3.1.

PR #561 by @hesperine completes the remaining part of GitHub #484: the banned-member tooltip was already added
by PR #494 in 0.2.5, but the strategy draft could not revisit the briefing's special enemies, leader and battlefield.

The maintainer accepted this as a convenience in the [initial review](https://github.com/sganggs/Stronghold-Protocol/pull/561#issuecomment-6144292092)
and confirmed the existing modal interaction on 2026-10-16
([follow-up](https://github.com/sganggs/Stronghold-Protocol/pull/561#issuecomment-6198380140)). The official client has
no such button; it only repeats information already announced in the briefing, without changing the game rules.

Now the entry under the strategy order reads 本局信息. The shared `ui/matchEnemies.js` `MatchEnemies` blocks show
the announced leader's icon, name, abilities and final-assault round, the battlefield, and each special enemy type's
icon, name and description. They read the same existing `m.public` fields (`bossId`, `stageId`, `factions`) and
localized lookups as the briefing. The existing `ui/matchInfo.js` blocks and banned-member hover tooltips are reused.

The dialog stays modal and read-only while choosing or waiting for a teammate: close, Escape or the backdrop closes
it; clicking the backdrop over the confirmation button closes only the dialog and does not pick a strategy. Closing
preserves the highlighted strategy, the countdown keeps running, and a turn change closes the dialog automatically.
On smaller windows and landscape phones its body scrolls while the close button and turn status remain visible.
There is no layout change to expose or operate the background controls while the dialog is open, as the maintainer
confirmed. No new [ASSUMED] rule, data, protocol or simulation change. Normative: [client.md §10](../design/client.md)
and [PLAYING.md](../PLAYING.md).

Tests: `test/ui/match-info.test.js` (the shared information and localized/fallback enemy data),
`test/ui/match-info.e2e.test.js` (real server and Chrome: briefing/dialog consistency, banned-member hover,
close/escape/backdrop without a selection, selected strategy preserved, live countdown and turn-change closing;
1000, 1001, 1024, 1120 and 1280 px windows with every information block reachable by scrolling and background
controls usable after closing; 1920×1080 desktop and 844×390 / 756×366 landscape phones).
Golden: unchanged (client information only).
